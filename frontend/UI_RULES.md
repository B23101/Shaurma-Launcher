# Правила інтерфейсу (для людей і ШІ-асистентів)

Прочитай це ПЕРЕД будь-якою зміною UI: налаштування лаунчера, збірки, сервера, діалоги, тости, тексти.
Мета: мінімалізм, швидко знаходиться, нічого зайвого. Гравцям не подобається, коли налаштування «десь у жопі» й
навколо купа тексту.

## 1. Один вигляд налаштувань усюди
- Налаштування лаунчера, збірки й сервера малюються ОДНИМИ компонентами/класами: рядок `.st-row`
  (`settings.css`) або `SettingRow.svelte`. Новий рядок налаштування = той самий рядок. Свій «унікальний» вигляд — заборонено.
- Рядок: **назва** зліва, **контрол** справа (перемикач, список, поле). Під назвою — максимум ОДНА коротка підказка.
- Технічні деталі (ключ файлу, «типово», діапазон) — у згорнутому `<details>`, не на видноті.
  Виняток — підказки про безпеку/втрату даних (білий список, online-mode тощо).
- Групи за змістом, найчастіше потрібне — вгорі. Порядок і назви груп однакові в усіх трьох місцях, де є схожі речі.
- Нове налаштування кладемо туди, де його шукатиме гравець (див. §4), а не «куди влізло».

## 2. Тексти: менше — краще
Бюджет (перевіряє `backend/ui_text_budget_test.go`):
- підказка/опис/інтро (`*Desc`, `*Hint`, `*.hint`, `*.desc`, `*Sub`, `*Note`, `*Intro`) — **до 140 символів**;
- підказка параметра `server.properties` (`props.<ключ>.hint`) — **до 80 символів**.

Як писати:
1. Не повторюй назву: «Анімації» → підказка не «Вмикає анімації».
2. Одне речення. Без «Ви можете…», «Зверніть увагу…», «Це дозволяє…».
3. Не пояснюй очевидне й не розповідай, як це працює всередині. Лише наслідок для гравця.
4. Не дублюй текст у шапці, підвалі, підказці й тултіпі одночасно. Одне місце.
5. Числа й одиниці — у контролі (`хв`, `МБ`, «0 = вимкнено»), не в абзаці.
6. Не пиши історію версій («прибрано в 1.21.9…») — лише коротко «→ /gamerule pvp».
7. Без маркетингу й вигуків. Без «просто», «легко», «автоматично» заради слова.
8. Підтвердження: заголовок = дія, текст = що буде втрачено/збережеться, ≤ 2 короткі речення.

## 3. Попередження
- Показуй попередження ЛИШЕ коли є реальний ризик: втрата даних, безпека, необоротна дія.
- Не показуй «інформаційні» плашки там, де достатньо підказки. Не дублюй попередження в рядку й у діалозі.
- Те, що можна відновити («нічого не видаляється»), — не привід для червоного блоку. Один короткий рядок.
- Один екран — не більше одного постійного банера. Решта — тости й підказки за потреби.

## 4. Де що живе
- **Налаштування лаунчера** — вигляд, мова, продуктивність, пам'ять і кеш, акаунт, сповіщення, інтеграції.
- **Налаштування збірки** — версія/лоадер, пам'ять і Java, запуск і вікно, мод-джерела, ярлики. Те, що стосується ОДНІЄЇ збірки.
- **Налаштування сервера** — `server.properties`, ядро/Java, мережа, доступ, бекапи. Те, що стосується одного сервера.
- Одна й та сама річ не живе у двох місцях. Якщо потрібен доступ звідусіль — посилання «Відкрити в налаштуваннях».
- Пошук налаштувань має знаходити новий пункт: додавай назву й ключові слова.

## 5. Технічні правила
- Усі тексти — через i18n (`frontend/src/lib/langs/uk.json` і `en.json`) ОДНОЧАСНО. Жодних рядків у розмітці.
- Не форматуй JSON цілком і не чіпай CRLF: правиш тільки свої ключі, щоб не роздувати diff.
- Схема налаштувань лаунчера — `backend/internal/config/schema.go` (одне джерело; UI малюється зі схеми).
- Нові стилі — з токенів теми (`var(--…)`), без жорстких кольорів, крім бейджів стану. Працює у світлій і темній темі.
- Клавіатура й фокус: інтерактивний елемент — `<button>`/`role`, `aria-label` для іконок.
