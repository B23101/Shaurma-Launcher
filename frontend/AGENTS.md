# Правила інтерфейсу Shaurma Launcher

Дотримуйся цих правил для всіх екранів лаунчера, збірок і серверів.

## Тексти

- Спочатку виріши, чи потрібен текст. Якщо назви й контролу досить для дії, видали підпис повністю разом із порожнім блоком.
- Потрібна підказка: одне коротке речення, орієнтовно до 60 символів. Пиши результат або наступну дію.
- Не повторюй назви кнопок, вибрані значення, статуси й лічильники.
- Не додавай рекламних обіцянок, службових вступів, списків переваг чи пояснень внутрішньої реалізації.
- Українська мова; зберігай наявне звертання на «ти» чи «ви». Якщо контекст змішаний, пиши безособово.
- Технічні ключі, внутрішні шляхи й параметри протоколів не повинні займати основний екран. Залишай їх у розкривних деталях, коли вони потрібні для ручного налаштування.
- Не ховай попередження про втрату даних, відкриття доступу чи витік особистих даних у підказках. Скороти їх, зберігши наслідок.
- Не обіцяй захисту, якого немає: білий список сам по собі не перевіряє власника ніка, а шифрування на сервері не є наскрізним.
- Зберігай ключі перекладів, підстановки та переноси CRLF у uk.json. Не змінюй інші мови без запиту.

## Налаштування

- Використовуй спільні компоненти й стилі з lib/settings: SCard, st-nav, st-row, st-switch та StSelect.
- Вхід у налаштування має називатися «Налаштування» і бути видимим у навігації відповідної збірки чи сервера.
- Усередині використовуй короткі розділи за завданням гравця. Основні параметри доступні одразу; технічні подробиці розкриваються окремо.
- Один рядок: назва зліва, значення чи перемикач справа. Однакові відступи, розміри контролів і фокус у всіх трьох типах налаштувань.
- Не додавай оглядових лічильників, рекламних карток і повідомлень «усе добре» над основними параметрами.
- Пошук має знаходити параметр за зрозумілою назвою та технічним ключем, якщо він є. Не підмінюй пошук параметрів фільтром лише назв розділів.
- Для ручного збереження використовуй одну видиму панель змін. Не втрачай незбережені значення при переході між розділами.
- Не ховай основні дії в меню з трьома крапками. Підтвердження потрібне для небезпечних дій, а не для кожного перемикача.

## Доступність і перевірка

- Для дії використовуй button, для переходу — посилання. Не створюй клікабельний div, якщо підходить нативний елемент.
- Кнопка лише з іконкою повинна мати змістовний aria-label. Підказка при наведенні сама по собі його не замінює.
- Перемикач має доступну назву й стан. Усі дії мають працювати з клавіатури; фокус повинен бути видимим.
- Не маскуй попередження через svelte-ignore, вимкнення діагностик чи формальні role без правильної поведінки.
- Після видалення елементів прибирай лише справді невикористані стилі. Не видаляй стилі динамічного вмісту навмання.
- Перед редагуванням кожного екрана розділи тексти на: прибрати, скоротити, залишити. Перевір і умовні стани, а не лише перший екран.
- Після змін запускай svelte-check та перевіряй збірку. Порівнюй кількість попереджень до й після.
- Перевіряй змінені екрани візуально, з клавіатури та у вузькому вікні. Не стверджуй, що перевірено весь інтерфейс, якщо перевірено лише код або кілька екранів.
- Записуй зміни в кореневий PENDING_CHANGES.md; не виконуй git commit.
